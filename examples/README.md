### xiaohongshu - 小红书风格转换

**输入：**
```
互联网泡沫时期，纳斯达克从5000点跌到1000点，跌幅80%。
但即使是亚马逊、思科这样的好公司，也跌了90%以上。
这说明在泡沫破裂时，估值体系会整体重构，好公司也难逃一劫。
```

**输出：**
```markdown
# 互联网泡沫，好公司也跌了90%

2000年互联网泡沫破裂，纳斯达克从5000点跌到1000点。

很多人以为，只要买的是好公司，就能躲过崩盘。

但现实是：亚马逊跌了95%，思科跌了89%，这些后来证明是伟大的公司，当时一样跌到怀疑人生。

**泡沫破裂时，估值体系会整体重构。**

不是公司不好，是所有人都在重新定价「一家互联网公司到底值多少钱」。

2000年大家觉得「未来」值100倍PE，2002年觉得只值20倍。估值锚点变了，所有船都会下沉。

就像股票市场一样。追求模糊的正确。

#投资 #互联网泡沫 #估值 #风险管理
```

## 思维视角类

### steve-jobs-perspective - 乔布斯视角

**示例对话 1：产品决策**

```
用户：我们的 SaaS 产品功能越来越多，但用户留存在下降，要不要做减法？

乔布斯：你问错了问题。

不是「要不要做减法」，是「为什么你一开始就在做加法」。

功能多 ≠ 产品好。你现在有多少功能？50个？用户真正用的有几个？
我猜不超过5个。

那其他45个功能是给谁做的？是用户要的，还是你们产品会议上妥协的结果？

Focus means saying no to 100 good ideas.
不是说no到烂主意，是说no到「听起来不错但会分散注意力」的主意。

你现在要做的不是「减法」，是回到原点：
这个产品最核心要解决的问题是什么？一句话说清楚。

然后砍掉所有不直接服务于这个核心的功能。
不是藏起来，是删掉。

留存下降不是因为功能少，是因为用户找不到他们要的那个功能。
```

**示例对话 2：技术选型**

```
用户：我们在纠结用 React 还是 Vue，团队意见不统一

乔布斯：Stop.

这不是技术问题，是你没有清晰的产品愿景。

如果你知道要做什么产品，技术选型就不是问题。
技术是为产品服务的，不是反过来。

问你自己：
- 这个产品的核心体验是什么？
- 哪个技术栈能让你最快验证这个体验？
- 你的团队最熟悉哪个？

React vs Vue 的争论，90%的情况下都是在浪费时间。
两个都能做出好产品，也都能做出垃圾。

关键是：你有没有一个清晰到可以用一句话说清楚的产品定义？

如果没有，先别写代码。
```

## 自动化工作流类

### xhs-content-generator - 小红书投资内容生成

**调用：**
```
/xhs-content-generator MACD
```

**输出：**
```markdown
# 小红书内容_2026-05-30.md

## MACD金叉就该买？很多人亏在这里

很多人把MACD金叉当买入信号，结果买完就套。

MACD的本质是趋势指标，不是买卖点指标。

**金叉只是告诉你：短期均线上穿长期均线了。**

但这个信号有个致命问题：滞后。

等MACD金叉出现时，股价往往已经涨了一波。你这时候追进去，可能正好买在短期高点。

更危险的是震荡市。

在横盘震荡时，MACD会频繁金叉死叉，每次都是假信号。你要是每次金叉都买，每次死叉都卖，手续费都能亏掉10%。

**MACD真正有用的场景：趋势确认。**

不是用来抓买点，是用来确认趋势是否延续。

比如上涨趋势中，MACD在零轴上方金叉，这是加仓信号，不是开仓信号。

MACD是辅助工具，不是决策依据。

#投资 #技术分析 #MACD #股票

[第二篇内容...]

---
```
